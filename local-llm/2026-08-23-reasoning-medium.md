# 作業メモ：LM Studio の思考量を xhigh → medium に変更

**日付:** 2026-08-23
**対象:** Qwen3.8-27B（orcarouter 改変版 / MLX）
**環境:** MacBook Air M4 24GB ＋ LM Studio（Local Server 起動中）

## 1. 結論

チャットテンプレート（Jinja）の1行だけを書き換え、思考の深さの既定値を
xhigh → medium にした。UIに設定項目が出ないモデルでも恒久的に効く。

    {%- set resolved_reasoning_effort = reasoning_effort|default('medium') %}

## 2. なぜやったのか

既定が xhigh（最も深く考える）で、待ち時間が実用に耐えなかった。
medium にすると待ち時間が大きく減り、品質低下は計測されなかった。
つまり「賢くする設定」ではなく「無駄に長考させる設定」が初期値だった。

## 3. 回り道の記録（3段階の誤解）

| 段階 | 見立て | 実際 |
|---|---|---|
| 1 | medium は無いはず | 誤り。別形式の報告に引きずられた |
| 2 | 公式版なら選択欄がある | 正しいが、この改変版には出なかった |
| 3 | モデルが非対応では | 誤り。テンプレートは3段階に完全対応していた |

教訓：「UIに無い」は「機能が無い」ではない。中身を見る。

## 4. medium の正体

low と xhigh は指示文をシステムプロンプトに注入する。
medium は分岐が存在せず、何も注入しない＝モデル本来の素の状態。
Reasoning Effort の正体は「一文の注入」にすぎない。

## 5. 手順

1. モデルの「…」→ Edit Chat Template
2. 元のテンプレートをバックアップ
3. default('xhigh') を default('medium') に変更
4. 保存 → モデルを Eject → 再ロード

Eject が必須な理由：テンプレートは読み込み時に適用されるため、
稼働中のモデルには反映されない。

## 6. 確認方法（数字で検証）

短い質問を API に投げ prompt_tokens を見る。
11 前後 = xhigh の指示文（約40トークン）が入っていない = medium。
Jinja が文字列化されていれば 1,000 超になるので、
貼り付け場所の正しさも同時に検証できる。

## 7. 使い分け

| 用途 | 設定 |
|---|---|
| 単純な確認 | low |
| スクリプト生成・ログ解析 | medium（既定） |
| 原因不明の障害解析 | xhigh |

## 9. 一行で残すなら

思考量は「モデルの性能」ではなく「テンプレートが注入する一文」で決まる。
UIに項目が無くても、テンプレートを1行直せば制御できる。

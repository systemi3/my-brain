# LM Studioのモデルが止まらなくなった件（aider暴走）

## ① 何をしたかったか

MacBook Air の aider から、ネットワーク越しに Mac mini の LM Studio
（`qwen3.6-35b-a3b-mlx`）に接続し、挨拶程度の短い入力をしただけ。

```
> こんにちは
```

## ② 何が起きたか

文字が延々と流れ続けて止まらなくなった。
さらに **aiderを強制停止して再起動しても、LM Studio側は動き続けた。**

LM Studio の画面に出ていた異常値：

```
0 GEN 110,911 tok
```

挨拶1回に対して11万トークン。通常の返答は数十〜数百トークン。

## ③ どう理解したか

### 学び1：クライアントを殺してもサーバーは止まらない

```
Air(aider)  ──HTTPリクエスト──▶  Mac mini(LM Studio)
  クライアント                       サーバー
  ここを殺しても                    ここは動き続ける
```

生成という処理はサーバー側で走っている。クライアントは結果を受け取っているだけ。
**電話を切っても、相手が喋り続けているのと同じ。**

→ 正しい止め方は「サーバー側でモデルをアンロードする」。

### 学び2：aiderが未知のモデルだと「ブレーキ」を送れない

暴走時に出ていた警告がヒントだった。

```
Warning for openai/qwen3.6-35b-a3b-mlx:
Unknown context window size and costs, using sane defaults.
```

aiderがこのモデルのコンテキスト長・出力上限を知らない
= 「何トークンで打ち切れ」という指示を送っていなかった。

### 学び3：モデル側が「終わり」を出せないことがある

aiderは挨拶でも裏で巨大なプロンプト（システムプロンプト＋リポマップ）を送っている。
「ファイル全体を出力せよ」と指示されたモデルに「こんにちは」と言うと返す物がない。
→ それっぽいファイルを延々と創作し続け、停止トークン(EOS)を出すきっかけを失う。

MLX変換モデルはチャットテンプレートやstop文字列が正しく設定されていないことがあり、
これが起きやすい。

### 学び4：35Bクラスでも「それらしい嘘」をつく

`/ask` で確認したところ、`path/to/screenshot.png` という
**実在しないファイル名を創作**していた。出力は必ず検証すること。

### 学び5：14Bと35Bの使い分け

14Bは「照合」は得意でも「推論」は苦手。
❌「ありえないパターンを考えて」
✅「波及時間がマイナスの行を抜き出して」（機械的な条件抽出に落とす）

## 教訓

- **止まらないときは、まずどちら側（クライアント/サーバー）の問題かを切り分ける**
- 設定で解決できないこともある。その場合は「止める」ではなく
  **「枠を広げる＋タスクを小さく刻む」**
- 動いた/動かないより、**なぜそうなるかの構造**を覚える方が応用が利く
